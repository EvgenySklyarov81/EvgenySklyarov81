### 🔄 [auto-and-deploy](https://github.com/EvgenySklyarov81/auto-and-deploy) | Автоматизированный ETL-пайплайн симуляции продаж

**Суть задачи:** Инженерно-технический проект по созданию автоматического конвейера данных (ETL). Написан скрипт для регулярной генерации данных о продажах и их загрузки в базу данных.

* **Что сделано:**
  * Разработан модульный Python-скрипт для генерации данных о продажах. Реализовано бизнес-требование: календарь исключает воскресенье, так как в этот день у компании нет продаж.
  * Реализована модульная архитектура кода: функции генерации и записи данных вынесены в отдельные `.py` файлы и импортируются в главный скрипт.
  * Написан ETL-конвейер, собирающий локальные файлы (`OS`, `Glob`) и загружающий их в базу данных **PostgreSQL** с использованием библиотеки `psycopg2`.
  * Реализовано безопасное хранение доступов к БД в отдельном файле конфигурации через `configparser`.
  * Настроена автоматизация пайплайна: запуск по расписанию (раз в сутки, кроме воскресенья) через `crontab` (Linux) и планировщик задач Windows.

* **Стек:** Python (Pandas, NumPy), PostgreSQL, psycopg2, configparser, crontab / Task Scheduler.

* **Точки роста:** 
  * Добавил бы логику обработки сбоев при транзакциях (транзакционность через `try-except` в `psycopg2`).
  * Реализовал бы проверку на дубликаты данных (например, очистку или перезапись данных при повторном запуске за тот же день, чтобы избежать дублирования строк при технических сбоях).

### 📊 [business-model-analysis](https://github.com/EvgenySklyarov81/business-model-analysis) | Маркетинговый и продуктовый анализ бизнес-модели в Google Таблицах

**Суть задачи:** Комплексный анализ текущих показателей компании и оценка финансовой целесообразности расширения торговой сети (открытия магазина в новом городе).

* **Что сделано:**
  * Проведен **когортный анализ**: рассчитан коэффициент удержания (Retention Rate) покупателей по неделям для отслеживания стабильности клиентской базы.
  * Построена модель **юнит-экономики** для каждой отдельной когорты клиентов.
  * Оценена эффективность маркетинга: рассчитан возврат инвестиций в рекламу (**ROI**) в разрезе каналов привлечения и городов присутствия. 
  * Выявлены лидеры и аутсайдеры среди каналов: высокую эффективность показали **SEO (ROI 120%)** и **CPC Adwords (ROI 108%)**, в то время как CPC Direct (76%) и SMM (41%) оказались убыточными.
  * Определены ТОП-3 самых эффективных городов по окупаемости: Москва (42%), Санкт-Петербург (39%) и Екатеринбург (30%).
  * Сформировано заключение для бизнеса: рекомендовано расширение в крупные города Урала и Сибири, так как они географически близки к производству и складам компании, что оптимизирует логистику.

* **Архитектура решения:** Проект реализован онлайн в Google Таблицах на базе симулированного бизнес-датасета. Вся работа выполнена с акцентом на удобство пользователя: настроен «нулевой» лист-оглавление для навигации, расчеты изолированы на «служебных» вкладках, а финальные бизнес-выводы вынесены на отдельный лист.

* **Стек:** Google Таблицы (VLOOKUP, Pivot Tables).

### 🗄️ [rfm-analyses-sql](https://github.com/EvgenySklyarov81/rfm-analyses-sql) | Сегментация клиентов (RFM-анализ) в PostgreSQL

**Суть задачи:** Разделение клиентской базы на группы по частоте (Frequency), новизне (Recency) и сумме (Monetary) покупок на основе истории транзакций.

* **Что сделано:**
  * Написан SQL-запрос для расчета метрик RFM на основе сырых данных о заказах.
  * Реализована логика распределения клиентов по сегментам с использованием агрегатных выражений и оконных функций.
  * Разработан скрипт на Python для построения графика распределения покупателей, позволяющий наглядно оценить структуру получившихся групп.
  * Сформирована финальная таблица с результатами сегментации (в README оформлена в виде компактного спойлера).
  * Подготовлен блок рекомендаций по взаимодействию с каждым сегментом пользователей.

* **Стек:** SQL, PostgreSQL, Python (Pandas, Matplotlib), DBeaver (интерфейс работы с БД).
